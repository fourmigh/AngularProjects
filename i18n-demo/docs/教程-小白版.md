# i18n-demo 小白入门教程（大白话版）

> 这份文档是给**零 Angular 基础**的同学看的：用表格和打比方的方式，讲清楚这个 demo 里的三种国际化方案到底差在哪、文件怎么放、新手该注意什么。
> 想深挖原理、脚本细节、加新语言的完整步骤，请去看同目录下的 `i18n方案对比.docx` 和 `i18n方案对比.xlsx`（那是给开发者看的深度文档）。

---

## 一、30 秒看懂这个 demo 在干什么

这个网站用 **Angular** 写成，里面展示了**同一套界面用三种方式做多语言**。

先记住三个最基础的词（后面全靠它们）：

| 词 | 大白话解释 | 类比 |
| --- | --- | --- |
| `i18n` | 让软件支持多种语言 | 给 App 装上"多国语言包" |
| `locale` | 具体的某一种语言 | `zh`=中文、`en`=英文、`de`=德文 |
| `翻译键 @@id` | 每一句要翻译的话的"身份证号" | 快递单号：凭它找到对应的译文 |

所谓"国际化"，本质就三步：
1. 在代码里给每句话贴一个**翻译键**（比如 `@@demo.title`）；
2. 准备一张"**键 → 各语言译文**"的对照表；
3. 运行时按当前语言去表里查，把原文换成译文显示。

三种方案的区别，只是**第 2、3 步"什么时候做、用什么格式存、能不能随时换"**不同。

## 二、三种方案一句话对比

| 方案 | 一句话比喻 | 翻译文件 | 切换语言 |
| --- | --- | --- | --- |
| 官方运行时 | 同一辆车，路上随时换语音包 | `assets/locale/{zh,en,de}.json`（按 locale 加载） | 点按钮立刻换，不用重新打包 |
| 官方编译时 | 每种语言单独印一版书 | `messages.zh.xlf` / `messages.de.xlf` | 每个语言是一个独立站点，不能中途换 |
| 自研方案 | 自带一个可视化翻译后台 | `translations.json`（主文件）+ `assets/locale/*.json`（运行时加载） | 点按钮换 + 网页里直接改译文即时生效 |

## 三、核心对比表（你最关心的部分）

| 对比项 | 官方运行时<br>`$localize` + `loadTranslations` | 官方编译时<br>`extract-i18n` + `--localize` | 自研方案<br>`t()` / `label()` + JSON + codegen |
| --- | --- | --- | --- |
| demo 页面地址 | `/official` | `/compile-time` | `/custom` |
| 一句话定位 | 一个站点，运行时随时切换 | 每种语言一个固定站点 | 统一翻译源 + 类型安全 + 可在线改 |
| 怎么构建 | 打**一**个包 | 每种语言各打**一**个包 | 打**一**个包 |
| 怎么切换语言 | 按钮即时切换，刷新页面不丢（存 localStorage） | 不能切换，语言由网址决定（如 `/zh/`） | 按钮即时切换，也能在编辑器里改译文即时生效 |
| 网址是否带语言 | 不带（如 `/official`），语言记在内存/localStorage | 带（如 `/zh/`、`/de/`），由 `base href` 决定 | 不带（如 `/custom`），语言记在内存/localStorage |
| 翻译文件长啥样 | `assets/locale/{zh,en,de}.json`（按 locale 加载，`loadTranslations` 直接消费） | `messages.zh.xlf`（XML 格式，有 `<source>`/`<target>`） | `translations.json` 是唯一主文件（脚本源）+ `assets/locale/*.json`（运行时加载） |
| 拼错键名会报错吗 | 不报错，但会显示原文 | 不报错，缺译文显示原文 | **会**（有 `TranslationKey` 类型，编译期就拦住） |
| 能网页里直接改译文吗 | 不能（要改文件重新加载） | 不能（要重新构建站点） | **能**（Monaco 编辑器 → 应用即生效） |
| 包体积 | 一个 bundle，含全部语言 | 每个语言一个静态站点，可 tree-shake 更小 | 一个 bundle，含全部语言 + 编辑器（稍大） |
| 最适合谁 | 要用户免刷新切换、小项目 | 要 SEO/性能、每种语言独立部署 | 翻译统一管理、要类型安全、产品同学要能在线改 |

> **tree-shake（摇树）**：打包时把"用不到的代码"像摇树一样抖掉。编译时方案每种语言只留自己的译文，所以体积最小。
> **localStorage**：浏览器里的小本本，关掉网页再打开还记得你上次选的语言。

> 💡 **运行时到底读哪个文件？（很多人会搞混）**
> 官方运行时和自研方案**共用同一个 `I18nService`**，运行时都从 **`assets/locale/{zh,en,de}.json`**（按当前语言加载对应那份）取译文，再 `loadTranslations` 注入官方注册表。两者区别只在组件写法：官方直接写 `$localize`，自研写 `i18n.t('键')`。
> 而 **`translations.json` 是唯一主文件**，只给脚本（`check` / `make-xlf` / `split`）当数据源用，运行时不直接加载它；`assets/locale/*.json` 就是 `split-i18n.mjs` 从主文件拆分出来的"每语言独立文件"，由运行时直接消费。

│  │  ├─ editor/editor.component.ts  // 网页里的 Monaco 翻译编辑器

│  │  └─ scripts/

│  │     ├─ make-xlf.mjs             // 把主文件译文注入到 messages.zh.xlf / messages.de.xlf
│  │     └─ check-i18n-keys.mjs      // 校验：键是否齐全、有没有孤儿键
│  │
│  ├─ locale.service.ts              // 全局语言状态（signal + localStorage）
│  ├─ app.component.ts/html          // 外壳：导航按钮、URL/内存切换 go()

## 五、我该选哪个？（场景决策表）

| 如果你的需求是… | 选 |
| --- | --- |
| 用户要在页面里**免刷新随时切换**语言 | 官方运行时 |
| 追求**体积最小、SEO 好**、每种语言独立部署（如 `/zh/`、`/de/`） | 官方编译时 |
| 翻译**统一管一份**，要**类型安全**（拼错键编译就报错），还希望**产品同学能网页里直接改** | 自研方案 |
| 只是想快速看懂 i18n 怎么玩 | 随便进 `/official` 或 `/custom` 点点看 |

## 六、5 分钟跑起来

```bash
# 1. 安装依赖（装完会自动跑 patch-package）
npm install

# 2. 启动"运行时 + 自研"站点（默认 http://localhost:4200）
npm start

# 3. 想看"编译时"方案，另开一个终端：
npm run build:compile      # 生成 dist/i18n-demo/browser/{,zh,de}
npm run preview:compile     # 本地预览编译时站点（默认进 /zh）
```

常用命令速查：

| 命令 | 干啥 |
| --- | --- |
| `npm start` | 校验 + 拆分 + 启动开发服务器（运行时/自研） |
| `npm run i18n:check` | 检查翻译键是否齐全、有没有多余键 |
| `npm run i18n:split` | 读 `translations.json` 主文件，生成类型文件 + 拆分出每语言 json（运行时加载用） |
| `npm run i18n:extract` | 扫描代码，生成 `src/locale/messages.xlf` |
| `npm run i18n:make:xl` | 把主文件译文注入到 `messages.zh.xlf` / `messages.de.xlf` |
| `npm run build` | 构建运行时 + 自研站点 |
| `npm run build:compile` | 构建编译时多语言站点 |
| `npm run preview:compile` | 预览编译时站点 |

## 七、小白最该懂的 4 个原理

### 1. 翻译键 `@@id` 是怎么找到译文的？
代码里写 `$localize`:@@demo.title:Angular Native i18n Demo``，意思是："这句的身份证是 `demo.title`，默认显示英文，但如果有别的语言译文就替换"。
系统内部有一张"注册表"：`{ demo.title: "Angular 原生 i18n 演示"(中文) }`。渲染时拿着 `demo.title` 去表里查，查到啥就显示啥。

### 2. 运行时切换为什么能"点一下马上变"？
自研方案里：点语言按钮 → 按当前语言去 `assets/locale/{locale}.json` 取译文、调用 `loadTranslations(新语言映射)` 把注册表换成新语言的词典 → 再用一个 `renderTick`（刷新计数器）+1 强制画面重画 → 界面立刻变成新语言。
官方运行时方案和自研方案**原理一样**（共用 `I18nService`），区别只在组件里是写 `$localize` 还是 `i18n.t('键')`。

### 3. 编译时为什么是"静态站点"？
编译时方案在**打包那一刻**就把 `$localize(...)` 直接替换成了目标语言的正文。所以打出来的每个语言目录（如 `browser/zh`、`browser/de`）是写死的、独立的静态网站，运行时根本不查表——因此体积小、SEO 好，但也**不能中途换语言**，要靠不同网址区分。

### 4. 网页里改译文为什么能"写完就立刻变"？
自研方案里你能在网页右侧的 Monaco 编辑器直接改译文，点一下 **Apply** 页面当场就变。原理是"改注册表 + 强制重画"五步：
1. **编辑器预填 + 自动存草稿**：打开 `/custom` 页面，Monaco 里已经放好了合并后的翻译总表（`i18n.service.ts` 的 `getMergedContent()`）。你每敲一个字，`onDidChangeModelContent` 就把当前文本存进浏览器 `localStorage` 当"草稿"——所以没点 Apply 也能续写，刷新页面也不丢。
2. **点 Apply 校验**：按钮触发 `applyEdited(text)`（`i18n.service.ts:88`）。它先用 `parseMerged()` 校验 JSON 结构和语言是否合法（比如 `zh`/`en`/`de` 有没有写错）；不合法会提示错误，合法才继续。
3. **重新注册译文**：合法后调用 `applyLocale()`（`i18n.service.ts:227`）：用 `buildMap(当前语言)` 拼出 `{ 消息id: 译文 }` 这张新词典，先 `clearTranslations()` 清空官方 `$localize` 注册表，再 `loadTranslations(map)` 把新译文装进去。
4. **强制重画**：注册表一更新，`applyLocale()` 就让 `renderTick` 计数器 +1（`i18n.service.ts:233`）。而每个页面模板都用 `@for (bounce of [i18n.renderTick()]; track bounce)` 把整块内容包起来（`app.component.html`、`custom-page.component.html` 等）；`renderTick` 一变，Angular 就销毁并重建这块视图，模板重新去注册表里取译文。
5. **立刻看到新字**：模板重新执行 `i18n.t('键')` / `$localize`，这次从新注册表取到你刚改的译文，画面当场刷新——整个过程不刷新页面、不重新打包。

> 顺带：改完的结果（和草稿）都存进了 `localStorage`，关掉网页再打开还是你改的样子；点编辑器里的 **Reset** 会清空，回到 `translations.json` 主文件的原始译文。

## 八、新手常见坑

| 坑 | 说明 |
| --- | --- |
| 占位符 `{$USER}` 别乱删 | 译文里 `你好，{$USER}！` 的 `{$USER}` 是变量坑位，删了名字就填不进去了 |
| 动态内容要用变量传 | 像用户名、商品数量，要 `t('键', { USER: 名字 })` 传进去，不能写死在译文 |
| 自动生成的文件别手改 | `i18n-keys.ts`、`source-messages.ts` 会被 `split-i18n.mjs` 覆盖 |
| 编译时改完要重新构建 | 改了译文得重新 `i18n:extract` + `i18n:make:xl` + `build:compile` 才生效 |
| 自研方案"单一真相源"是 translations.json | xlf 文件是从它生成的，改 xlf 没用，要改主文件 |

## 九、大白话术语表

| 术语 | 大白话 |
| --- | --- |
| registry（注册表） | 系统内部那张"键→译文"的对照表 |
| loadTranslations / clearTranslations | 运行时"装入新词典 / 清空旧词典"的官方 API |
| tree-shake | 打包时抖掉用不到的代码，让体积更小 |
| base href / subPath | 站点根路径；编译时每种语言用 `/zh/`、`/de/` 区分 |
| localStorage | 浏览器小本本，记住你上次选的语言 |
| codegen（代码生成） | 用脚本自动生成 TS 代码（这里生成类型和映射） |
| TranslationKey | 自动生成的"合法翻译键"类型，写错键名编译就报错 |
| Monaco 编辑器 | 微软开源的代码编辑器（VS Code 同款内核），网页里用来改译文 |
| XLIFF / xlf | 翻译行业标准的 XML 文件格式，Angular 官方编译时专用 |
| ICU / 占位符 | 处理单复数、性别等复杂语法的写法，三种方案都支持 |
